  - 임베딩 차원: bge-m3면 **1024**, nomic이면 **768** → `curl`로 임베딩 1건 뽑아 벡터 길이 확인

    ```
    ollama run bge-m3-FP16.gguf  (또는) POST /api/embeddings 로 dimension 확인
    ```
- 만약 실제 bge-m3가 아니면 → 개발 PC에서 **정품 bge-m3 GGUF를 USB로 재반입** 필요.

## Q5. 리랭커 — 답변됨 ✅
- **초기부터 도입.** 성능 검증 후 하드웨어 상향 가능성 있음.
- 반영: **MVP에 리랭커 포함.** 기본 `bge-reranker-v2-m3`를 sentence-transformers(CrossEncoder)로
  **CPU 실행**(torch CPU wheel) → 질의 시 GPU는 LLM 전용 유지. 상향 시 GPU 이동(§design 2·5).

## Q6. HEX 특성 — 답변됨 ✅
- **프로토콜 문서 ~50개**, 문서당 **커맨드 10~30개**.
- HEX 저장 포맷 다양(.txt/.dat 등), 예시:
  1. `07/08 00:45:05 [00]-[00] (aee.txt)` — 타임스탬프 + `[]` 바이트 + `-` 구분자
  2. `07/08 00:45:05 [00][00] (coin.txt)` — 타임스탬프 + `[]` 바이트
  3. `[00][00][ab][cd] (eefe.dat)` — 타임스탬프 없음, `[]` 바이트
- 반영: HEX 파서가 (선택적)타임스탬프 제거 + `\[([0-9a-fA-F]{2})\]` 바이트 토큰 추출 +
  구분자 무시로 바이트 스트림 복원. 바이너리 .dat는 원시 hex 모드 폴백(§design 7).
