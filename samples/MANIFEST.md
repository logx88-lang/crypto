# 더미 샘플 세트 — 검토 게이트용 요약

> ⚠️ **검토 게이트**: 아래는 실제 자료가 없어 만든 **가상 더미**입니다. 실제 업무 자료와 대조하시고
> "실제는 이런 점이 다르다"고 알려주시면 샘플을 수정합니다. **승인 후에만** 이 샘플로
> 파싱→인덱싱→질의 E2E 테스트를 진행합니다.
>
> 생성기: `samples/generate_samples.py` (재현 가능) · 출력: `samples/dummy_set/`

## 설계 의도 (왜 이렇게 구성했나)
- **장비 2종**(XM-200 코인 컨트롤러 / TG-15 센서 게이트웨이)의 프로토콜 명세를 각각 **PDF·Word**로 만들어,
  HEX 분석 시 **후보가 2개 이상**이 되도록 했습니다 → "이 프로토콜이 맞습니까?" **UI 확인 단계**를 실제로 테스트.
- 두 규격의 **프레임 시작 바이트가 다름**(XM-200=STX `0x02`, TG-15=SOH `0x01`) → 잘못된 후보를 걸러내는지 검증.
- HEX 로그는 **XM-200 규격을 정확히 따르며**(체크섬 XOR 자체검증 통과), 주신 예시대로 여러 포맷으로 저장.

## 2. 통신 로그 (질의 시 업로드 입력물) — `dummy_set/hex/`
피드백(장비별 포맷 상이 + 자연어 로그 존재)을 반영해 **여러 변형**을 포함했습니다.

| 파일 | 포맷 | 예시(첫 줄) |
|---|---|---|
| `coin_log_dash.txt` | 타임스탬프 + `[XX]-[XX]`(구분자 `-`) | `07/08 00:45:05 [02]-[01]-[10]-[11]-[03]` |
| `coin_log_ts.txt` | 타임스탬프 + `[XX][XX]` | `07/08 00:45:05 [02][01][10][11][03]` |
| `aee.txt` | 타임스탬프 없음 `[XX][XX]` | `[02][01][10][11][03]` |
| `eefe.dat` | **바이너리 덤프** | `02 01 10 11 03 …` (원시 바이트) |
| `coin_log_space0x.txt` | **공백 구분 + `0x` 접두** | `07/08 00:45:05 0x02 0x01 0x10 0x11 0x03` |
| `sensor_log_tg15.txt` | **타 장비(TG-15)·방향표시 `[TX]/[RX]`·공백 hex·CRC16** | `07/08 01:10:00 [TX] 01 05 41 00 00 2D 85` |
| `event_log_natural.txt` | **자연어 로그(hex 아님)** | `2024-07-08 09:12:03 [XM-200] 코인 투입 감지: 1개, 잔액 500원` |

- XM-200 시나리오: 초기화→상태조회→코인 투입×2→잔액→500원 지급→하트비트→코인 투입→**잼→에러(0x01)**→리셋.
- 예: `[02][02][12][01][11][03]` = COIN_IN(0x12), 코인 1개, CHK=0x11 → **"코인 1개 투입"**.
- 설계 반영: **장비별 파싱 프로파일 + 자동 감지/확인**, **자연어 로그 별도 경로**(설계서 §7).

## 검토 요청 사항 (피드백 주시면 반영)
1. **프로토콜 명세 구조**: 실제 명세의 프레임/필드/명령표가 이와 많이 다른가요? (필드 폭, CRC 종류, 헤더 형태 등)
2. **HEX 포맷**: 실제 로그에 위 4가지 외 다른 형태가 있나요? (예: 공백구분 `02 01 10`, `0x` 접두, ASCII 혼합 등)
3. **문서 유형 비중**: 실제로 PDF/Word 비중이 이 정도인가요? 표가 훨씬 크거나 페이지가 많은가요?
4. **용어/약어**: 실제 장비명·명령어·약어 스타일과 유사한가요? (지금은 가상 장비명 사용)
5. **누락 포맷**: 위 세트에 빠진 실제 자료 유형이 있나요?
