# 검색 평가 하네스 (하이브리드 파라미터 튜닝)

하이브리드 검색(dense+BM25→RRF→리랭커) 구성을 **Recall@k / MRR** 로 비교한다.
LLM 호출 없음(임베딩+리랭커만) → 가볍게 반복 가능.

## 구성
- `eval_set.py` — 더미 문서 근거 질문 16개. 각 항목 `must_contain`(정답 근거 substring)로 관련성 판정.
  정확매칭(코드/ID→BM25 유리)과 의미/교차언어(→dense 유리)를 균형 배치.
- `run_eval.py` — 질문별 (임베딩·dense·bm25·리랭커점수)를 1회 캐시 → 파라미터 조합 인메모리 스윕.

## 실행
```bash
RAG_EMBED=bge-m3 RAG_RERANKER=BAAI/bge-reranker-v2-m3 python3 eval/run_eval.py
```
(사전: `data/` 인덱스 구축 + Ollama `ollama serve` + bge-m3, 리랭커 가중치)

## 결과 (2026-07-13, 더미 코퍼스 27청크, n=16)

| 구성 | R@3 | R@5 | MRR |
|---|---|---|---|
| **모든 rerank=on 구성**(가중치·rrf_k 무관) | 0.94 | 0.94 | **0.944** |
| hybrid 1:1 rerank=off | 0.94 | 0.94 | 0.874 |
| hybrid 1:2(bm25↑) off | 0.94 | 0.94 | 0.865 |
| dense-only off | 0.81 | 0.88 | 0.770 |
| bm25-only off | 0.88 | 0.88 | 0.790 |

## 결론
1. **리랭커가 최대 지렛대**: MRR 0.874→0.944. 리랭커 ON 유지(MVP 기본값). ✅
2. **하이브리드 > 단일 리트리버**: rerank 전 hybrid MRR 0.874 vs dense 0.77 / bm25 0.79 →
   두 리트리버 병용의 가치 입증. ✅
3. **가중치·rrf_k·rerank_top_n 은 이 코퍼스에서 무영향**(리랭커가 흡수) → **기본값 유지**
   (근거 없는 파라미터 변경 지양). 실제 ~100문서 코퍼스에서 재튜닝 여지.
4. **유일한 실패 = 표 희석**: "TG-15 ADDR 필드 의미"의 정답이 필드 여럿 섞인 큰 표 청크에 있어
   융합 7위→리랭커 9위로 저평가. **파라미터가 아닌 청킹 개선** 사안(행/필드 단위 표 청킹 후보).
